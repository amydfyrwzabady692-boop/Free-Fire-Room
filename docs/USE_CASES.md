# Use Case و Edge Case

## Use Caseهای نسخه اول

1. Onboarding: TOS، کانال اجباری، زبان/TZ
2. مشاهده فهرست با فیلتر امروز/آینده/حالت/منطقه/تأییدشده
3. ثبت‌نام با چک‌لیست شرایط
4. Referral معتبر پس از استارت + عضویت
5. Waitlist و ارتقا پس از انصراف/عدم صلاحیت
6. ویزارد برگزارکننده + پیش‌نویس + صف تأیید
7. ارسال رمز فقط به واجدین در زمان مقرر
8. اصلاح رمز پس از ارسال (نسخه جدید + پیام اصلاحیه)
9. لغو / تغییر زمان → Job و اعلان
10. Ban سراسری یا محدود
11. گزارش تخلف
12. Broadcast با تأیید نهایی
13. Export CSV شرکت‌کنندگان خود برگزارکننده
14. درخواست حذف حساب

## Edge Caseها

- دو کلیک همزمان «شرکت می‌کنم» → قفل ردیف، ظرفیت رد نمی‌شود
- خروج از کانال بین ثبت‌نام و ارسال رمز → ineligible، رمز ارسال نمی‌شود
- ربات از کانال حذف شود → شرط آن کانال منقضی/هشدار، کانال جدید بدون ادمین پذیرفته نمی‌شود
- کاربر ربات را Block کند → delivery permanent_fail
- Telegram RetryAfter → backoff
- Worker وسط ارسال کرش کند → deliveryهای SENT تکرار نمی‌شوند؛ بقیه با Job PENDING/FAILED دوباره
- Self-referral و دعوت تکراری نامعتبر
- Deep Link کاستوم لغوشده غیرفعال
- برگزارکننده به کاستوم دیگری دسترسی ندارد
- رمز هرگز در API لیست رویداد یا لاگ برنمی‌گردد
- ساعت تابستانی: ذخیره UTC، Job با datetime آگاه به منطقه
